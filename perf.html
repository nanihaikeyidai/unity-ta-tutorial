性能优化：看见浪费，才能动手砍

帧预算只有 16.6ms（60fps）。CPU 卡在提交，GPU 卡在填充或带宽——本章用互动仪表盘建立 Profiler 直觉。

本课目录

01 · SRP Batcher 02 · GPU Instancing 03 · Overdraw 04 · LOD 与 Profiler
LESSON 01

SRP Batcher：把「换材质」的税降下来

SRP Batcher 砍的是 CPU：减少 SetPass / CBUFFER 更新，不是减三角面。

📦 隐喻：没有 Batcher 时，每个包裹单独盖章寄出；有 Batcher 时，同一线路的包裹一起装车——车次（Draw Call）骤减。
  • Shader 需兼容：UnityPerMaterial / UnityPerDraw CBUFFER
  • 乱开 Material Keyword → Variant 爆炸 → 批被拆
  • Frame Debugger 里看是否标成 SRP Batch
Compatible HLSL 片段HLSL
CBUFFER_START(UnityPerMaterial)
  float4 _BaseColor;
  float4 _MainTex_ST;
CBUFFER_END
// 不要把每物体唯一的数据塞进 PerMaterial
🔴 Live · Draw Call Meter
开关 Batcher：同 Shader 多物体从「每物一次」变为少量合并提交（示意）。
LESSON 02

GPU Instancing：海量重复网格的正确姿势

大量相同网格、仅变换或少量属性不同 → GPU Instancing 一次提交画成千上万实例。

  • Batcher：多材质、同 Variant 的提交税
  • Instancing：同网格同材质的海量复制
  • 草、碎石、座椅 → 典型赢家
  • 避免每帧 new Matrix4x4[]；用持久缓冲 / Graphics.RenderMeshInstanced
Instancing 要点C#
mat.EnableKeyword("INSTANCING_ON");
Graphics.RenderMeshInstanced(rp, mesh, 0, matrices);
// URP Lit 默认支持；自定义 Shader 需 UNITY_SETUP_INSTANCE_ID
LESSON 03

Overdraw：同一像素被「粉刷」太多次

Overdraw：同一像素一帧内被写入太多次。半透明粒子、叠 UI、大面积 Alpha Blend 是重灾区。

🖌️ 隐喻：粉刷同一面墙刷八遍——墙不会更白，匠人（GPU）会累死。
  • Scene 视图 Overdraw 模式：越白越冤
  • 粒子：降数量、降屏幕占比、能 Alpha Cutoff 就别全程 Blend
  • UI：避免全屏半透明遮罩叠多层
🔴 Live · Overdraw Heat
拖动层数滑杆：热色区域 = 高 overdraw。目标是让画面「冷」下来。
LESSON 04

LOD 与 Profiler 心智模型

优化前先定性：CPU 逻辑 / CPU 提交 / GPU 谁在卡。三件套：Profiler · Frame Debugger · Rendering Debugger。

  • LOD：距离换面数；防爆闪可做交叉淡入或迟滞
  • 贴图压缩、图集、mip —— 带宽经常比算力更贵
  • 口诀：先量再砍 · 先大后小 · 先频率后常量
🩺 隐喻：Profiler 是听诊器。没有听诊器就开刀，叫「玄学优化」。
排查顺序Playbook
1. Game 视图开 Stats：看 Batches / Tris / Screen
2. Profiler：CPU 尖峰模块是谁？
3. Frame Debugger：哪几个 Pass 最肥？
4. 再决定砍灯、砍特效、砍分辨率或改 Shader
